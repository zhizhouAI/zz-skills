# zz-desktop-ops · 桌面操作规范

## 一句话

后台悄悄干，动钱动删先停手。

## 用与不用

适合用的场景：

- 用户让 Agent 上网页办具体事：查订单、填表单、导出数据
- 用户让 Agent 操作桌面 App：清文件、整理相册、批量改名
- 登录后的连续多步网页流程：下单、报名、退订
- 用户明确授权的重复性自动操作，比如每周导一次报表
- 把几个网站的数据搬到一张表里，比如比价、汇总订单

不该用的场景：

- 用户只是问「这个网页怎么操作」，要的是教程，不是代办
- 操作对象是别人的账号，或没拿到授权的设备
- 要过验证码、短信、人脸这类本人校验的环节，交给用户本人
- 法律签署、医疗确认这类高风险页面，建议用户亲手点

## 开工前要什么

必需信息：

- 要办的事：目标网站或 App、做到哪一步算完成

可选信息：

- 账号是否已登录，用哪个账号
- 允许的花费额度、允许删除的范围
- 操作结果存哪，要不要截图留证
- 要不要顺带核对结果，比如订单金额和购物车标价是否一致

用户没给时的默认假设：

- 能后台就后台：不开新的前台窗口，不移动用户鼠标，不抢输入焦点
- 没说范围就只做用户点名的动作，不顺手多做一些
- 付款默认上限 0 元：任何要花钱的动作都必须逐笔确认
- 没说留证方式，就默认每步截图存档，放进下载目录的独立文件夹

## 怎么做

1. 复述任务和完成标志
   - 做什么：一句话说清去哪、做什么、做完的标志是什么
   - 判断标准：用户能一眼确认理解没偏，特别是金额和对象
   - 中间产物：任务复述

2. 清点工具
   - 做什么：过一遍现有工具：浏览器自动化、文件操作、截图，
     每个步骤对应哪个工具
   - 判断标准：每个步骤都有工具可落，缺的单独列出来
   - 中间产物：工具清单

3. 缺工具先说明再引导
   - 做什么：说清缺什么、装了干什么用、有什么影响，
     用户同意后再引导安装
   - 判断标准：未获同意，一个软件都不装
   - 中间产物：缺工具说明

4. 只读试操作
   - 做什么：先浏览、查询、截图，确认页面状态和元素位置，
     不点任何会改数据的按钮
   - 判断标准：关键元素都定位到了，操作路径能走通
   - 中间产物：操作路径

5. 分步执行并留痕
   - 做什么：按路径一步步执行，每步记下做了什么、页面给了什么
     反馈，出错的步骤当场停
   - 判断标准：每步有记录，出错能指到具体哪一步；同一动作失败
     不自动重试，先报告
   - 中间产物：执行日志

6. 危险动作前停
   - 做什么：碰到付款、删除、发送，停下来发确认请求：列出将
     点什么、金额或对象是什么，等用户回「确认」
   - 判断标准：没有用户对这一笔的明确确认，绝不执行
   - 中间产物：确认请求与用户回复记录

7. 交付结果
   - 做什么：报告做了什么、到哪一步、留下什么凭证
   - 判断标准：结果和第 1 步说的完成标志对得上；没做完就说卡在
     哪一步，不硬凑「办好了」
   - 中间产物：操作报告

## 交付长什么样

背景：晚上九点半，用户对 Agent 说：「帮我在京东把购物车里那袋
89 块的猫粮下了，别的不动。」下面是这次操作的交付样式。

确认请求长这样（第 4 步之后暂停时发）：

```text
【确认请求】
将执行：支付 1 笔订单
金额：89.00 元（猫粮 1 袋，运费 0）
收货地址：默认地址「XX 市 XX 区幸福路 12 号」
其余 3 件购物车商品：未勾选、不受影响
回复「确认支付」才执行；要改地址请现在说；回复其他内容视为暂缓。
预计耗时：1 分钟内。支付渠道：默认银行卡，可在结算页改。
```

假如第 2 步发现缺浏览器自动化工具，第 3 步会先发一段说明：
「缺 XX 工具，用来驱动浏览器点页面；装完会多占约 200 MB 空间。
你同意我再装。」没点头之前，一个软件都不装。

操作报告长这样：

```text
【操作报告】2025-06-10 21:40
任务：京东购物车下单 1 袋 89 元猫粮，其余不动
方式：后台浏览器自动化，未占用前台窗口，未移动鼠标
步骤：
  1. 打开购物车，确认目标商品在（截图 01）
  2. 仅勾选该商品，其余 3 件未动（截图 02）
  3. 进结算页，地址为默认「幸福路 12 号」（截图 03）
  4. 21:36 发出确认请求，21:38 用户回复「确认支付，地址改公司」
  5. 改地址为「科技园 8 栋」，提交支付成功
     订单号 JD-20250610-8845123（截图 04）
危险动作记录：付款 1 笔 89.00 元，有用户确认记录
异常：无。结算页曾加载慢 5 秒，等待后正常，未重复提交
没做的事：没领任何优惠券，没开 PLUS 会员，没动其余商品
凭证：4 张截图在 ~/Downloads/jd-ops/，订单可在「我的订单」查到
核对结果：实付 89.00 元，与购物车标价一致
```

## 红线

- 付款、删除、发送三类动作，动手前必须有用户对这一笔的明确确认。
  检查方法：执行日志里能找到对应的确认请求和用户原话，
  「接着办」三个字不算数
- 全程默认后台：不移动用户鼠标、不抢占正在输入的前台窗口。
  交付里要写明用了后台还是前台
- 每一步执行必须留痕：截图或日志。出问题时要能指出卡在哪一步
- 缺工具先说明用途和影响，未经用户同意不装任何软件
- 验证码、短信、人脸等本人校验环节必须交还用户，不得尝试绕过

## 常见坑

- 把「让办事」当成「授权一切」，顺手领券、开会员、点收藏。
  用户没叫做的动作，一个都不要碰
- 出错后自动狂点重试，一次点击变成十次。失败就停下报告
- 只回一句「办好了」，不给订单号和截图，用户没法核对
- 在用户正打字的前台窗口里抢焦点，输入串到了别处
