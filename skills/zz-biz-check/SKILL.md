# zz-biz-check · 生意体检

## 一句话
四问拆生意，找最薄一环，明天动手第一步。

## 用与不用

适合用：

- 你经营一家店、一个产品、一门课或一项服务，觉得「哪里不对劲」，但说不清是获客、成交还是交付出了问题
- 收入在掉或者涨不动，想知道先修哪一段，而不是四处乱试
- 有人拿一个正在运转的项目问你「这生意还有救吗」，你要给出负责任的判断
- 打算投钱或全职加入某个项目，想先过一遍基本盘再决定
- 季度或年度复盘，想用一套固定问题过一遍，防止只看自己想看的

不该用：

- 用户一个数字都不肯给，只想要一句「能不能赚大钱」的保证
- 生意还在点子阶段，一个真实客户都没聊过——先去聊十个人，回来再体检
- 问题其实是执行细节，比如「这张海报不好看」，还没到生意结构层面

## 开工前要什么

必需：

- 生意一句话：卖给谁、卖什么、收多少钱
- 最近 3~12 个月的大致收入和客户数，估算也行，但要标「估」
- 用户最困扰的那一个问题，限一个

可选：

- 各获客渠道和大致成本
- 定价、退款率、复购率、续费率
- 团队人数和交付方式（人工 / 系统 / 外包）
- 试过哪些办法、放弃了哪些、为什么放弃

用户没给时的默认假设：

- 没有分渠道数据，就整体估算，报告里标明「口径：口述估算」
- 没有流失数据，现场追问「最近一个没再回来的客户是谁？走之前发生了什么？」
- 先按用户说的采信，但每条结论都挂上依据，方便事后核对

## 怎么做

全文沿用同一个例子：老陈的企业微信 SCRM 工具（B2B SaaS，年费 6800 元，去年 120 个客户，收入约 82 万）。他来时的原话是「感觉增长乏力」。

1. **收基线数字。**
   - 做什么：问清最近 3~12 个月的收入、客户数、单价。估算也算数，但要标「估」。
   - 判断标准：三个数齐了才开工；只说「还行」「不太好」就继续追问。
   - 中间产物：基线数字卡（收入 / 客户数 / 单价 / 时间段）。
   - 示例：问老陈。他答：「82 万，120 个客户，6800 一年，报表上的数。」——口径是报表，比口算可信。

2. **写下生意一句话。**
   - 做什么：一句话说清给谁、卖什么、收多少钱，说不清就先帮他磨。
   - 判断标准：外行一遍听懂，并且能举出最近一个真实客户的例子；举不出，说明对客户的认识还是想象。
   - 中间产物：生意一句话卡。
   - 示例：老陈先说「帮企业管客户」。追问后改成：「给 10~50 人的外贸公司，管企业微信上的客户，防客户被销售带走，年费 6800。」

3. **点名付钱的人。**
   - 做什么：列出最近付款客户的类型、客单价、付款频率，最好点名最近 5 单是谁。
   - 判断标准：能说出「最近 5 单分别是谁」；只说「都是企业客户」这种粗话就不合格。
   - 中间产物：付款人清单（类型 / 客单价 / 频次）。
   - 示例：问老陈「最近 5 单是谁？」答：「4 单是外贸公司老板，1 单是跨境代运营服务商。」——付款人比他以为的更集中。

4. **问为什么付。**
   - 做什么：把付款动机排序，区分「避免损失」和「想要好处」，用客户原话佐证。
   - 判断标准：至少一条动机能用客户原话复述；全是创始人自己的转译，就再去问一个客户。
   - 中间产物：动机排序表（动机 / 类型 / 佐证原话）。
   - 示例：一个客户原话：「就怕销售离职把客户带走。」——避免损失是主动机；官网写的「提升效率」是老陈的话，不是客户的话。

5. **查流失。**
   - 做什么：找最近走掉的客户，还原走之前最后发生了什么。
   - 判断标准：至少还原 2 个流失案例的具体过程；「客户没钱」不算答案，要问到没钱的背后最后一次互动是什么。
   - 中间产物：流失时间线（客户 / 走的时间 / 走前最后互动）。
   - 示例：老陈 Q3 走了 7 家，查后台发现其中 5 家走前 30 天没登录过，共同前兆是「录入嫌麻烦」。

6. **量漏斗，找最薄一环。**
   - 做什么：把获客→成交→交付→复购四段各配一个比例，横着比，找最薄那段。
   - 判断标准：四段至少两段有数字；最薄一环必须能用数字解释为什么是它。
   - 中间产物：漏斗估算表（环节 / 数值 / 来源）。
   - 示例：注册 400 家 → 试用 180 家 → 付费 26 家（14%）→ 次年续费 45%。最薄的是「试用后没养成录入习惯」，不是获客。

7. **连问三个为什么，找病根。**
   - 做什么：对着最薄一环连问三次「为什么会这样」，一层层往根上走（5-Why 的用法）。
   - 判断标准：问到「人 / 流程 / 产品机制」层面的原因才算到底；停在「客户懒」这种话不算。
   - 中间产物：病根卡（三层为什么 + 病根一句话）。
   - 示例：试用转付费低 → 为什么？14 天内没人录入 → 为什么？数据要从 Excel 一条条搬 → 为什么？产品没有「一键导入微信通讯录」。病根是缺导入功能，不是销售不努力。

8. **开出「明天第一件事」。**
   - 做什么：针对病根，给一个明天就能开始、两小时内能见初步动作的事。
   - 判断标准：动作具体到「给谁打什么电话 / 改哪页哪句话 / 排哪个功能进下个迭代」；反问「漏斗哪一格会变」，答不出就重写。
   - 中间产物：第一件事卡（动作 / 预期变化 / 完成标志）。
   - 示例：给 5 个「注册超 14 天、零录入」的试用客户各打一个电话，边聊边帮录前 10 个客户；同时把「一键导入」排进下个版本。预期：试用转付费从 14% 往 20% 动。

## 交付长什么样

```
# 生意体检报告：<生意名>（<一句话：给谁、卖什么、收多少>）

## 体检信息
- 日期：YYYY-MM-DD    期间：YYYY-MM ~ YYYY-MM
- 数据口径：口述估算 / 报表 / 现场追问

## 四问结论
1. 谁付钱：……（依据：最近 5 单是……）
2. 为什么付：……（客户原话：「……」）
3. 为什么流失：……（案例：客户A，走前最后互动是……）
4. 卡在哪一环：……（漏斗对比：……）

## 漏斗估算表
| 环节 | 数值 | 来源 | 状态 |
|------|------|------|------|
| 获客 | | | |
| 成交 | | | |
| 交付 | | | |
| 复购/续费 | | | |

## 最薄一环与病根
- 是哪一环：……
- 为什么是它：（数字对比）
- 病根：三层为什么的最后一层

## 明天第一件事
- 动作：<给谁、做什么>
- 预期变化：<漏斗哪一格、从多少往多少动>
- 完成标志：<怎么算做完>
```

老陈的报告里，「明天第一件事」填完是这样：

```
- 动作：明早 10 点起，给 5 个注册超 14 天、零录入的试用客户打电话，边聊边帮录前 10 个客户；下午把「一键导入微信通讯录」写进版本计划。
- 预期变化：试用转付费，从 14% 往 20% 动，下个季度验证。
- 完成标志：5 通电话打完，至少 3 家完成首次录入。
```

## 红线

- 每条结论后面必须跟「依据」：要么是用户给的数字，要么是一次具体提问的回答；没有依据的判断必须标「推测」
- 「明天第一件事」必须是动作句，不能是「提升转化」「加强服务」这类目标句；写完要能回答「漏斗哪一格会变」
- 最薄一环的结论必须带数字对比，比如「试用转付费 14%，远低于续费 45%」；拿不出对比就不许下结论
- 全文不出现口号式大词和商业黑话——写完做一次「删词测试」：任何删掉后句意不变的词一律删掉
- 每个数字注明来源（口述 / 报表 / 追问），估算标「估」

## 常见坑

- 只体检不开方：报告写得很厚，最后一句是「建议优化获客」。没有明天第一件事，等于没体检。
- 把创始人的乐观当数据：用户说「转化率大概 30%」，追问这数怎么算的；算不出来就按「估」处理，并调低对应结论的口气。
- 环节之间互相甩锅：获客怪产品、产品怪销售。用漏斗数字断案，谁的数字最差谁先动。
- 一上来就劝人关店：体检的目的是先修最薄一环；只有四问全部塌掉，才谈关停，并把判断过程写出来。
