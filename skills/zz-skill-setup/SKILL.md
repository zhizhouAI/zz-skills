# zz-skill-setup · 安装与更新

## 一句话

把 zz 技能装进你的 Agent、更新版本、清掉重复入口。

## 用与不用

**用：**
- 第一次把 zz-skills 装到某个 Agent
- 版本更新后同步本地技能
- 同一个技能在多个目录里出现，不知道 Agent 读的是哪份
- 只想装其中几个技能，不想全量

**不用：**
- Agent 有自己的插件市场且已提供 zz-skills 时，优先走市场安装
- 你要装的不是本仓库的技能（本技能只管 zz-skills）

## 开工前要什么

- 必需：目标 Agent（Claude Code / Codex / WorkBuddy / 其他支持 skills 目录的 Agent）
- 可选：只装哪几个技能；全局还是仅当前项目
- 默认假设：没说目标 Agent 时，检测本机已有的技能目录并让用户确认

## 怎么做

1. **定位来源**：确认 zz-skills 仓库在本机的路径（下文称 `<repo>`）。判断标准：`<repo>/skills/` 下能看到 `zz` 等目录
2. **定位目标**：常见目标目录——
   - Claude Code：`~/.claude/skills/`
   - Codex：`~/.codex/skills/`
   - WorkBuddy：其技能目录（以设置页显示为准）
   判断标准：目录存在即可写入；不存在则先创建
3. **选择范围**：全量装 `skills/` 下所有目录，或按名字只装指定的几个。判断标准：用户点名了技能就只装点名的，没点名就全量
4. **复制**：把每个技能目录整体复制到目标目录。命令形态：`cp -R <repo>/skills/<name> <target>/<name>`。判断标准：目标下出现同名目录且含 `SKILL.md`
5. **查重**：若其他目录（如项目级 `.claude/skills/`）也存在同名技能，列出来问用户保留哪份；不留两份，避免加载顺序混乱
6. **验证**：让用户在 Agent 里输入一个技能名（建议 `zz`），确认能被识别；不能识别时检查 frontmatter 是否完整、目录名与 `name` 字段是否一致
7. **更新**：更新 = 重复第 4 步覆盖同名目录。提醒用户：本地自己改过的技能会被覆盖，改过的技能先备份

## 交付长什么样

```text
【安装结果】
来源：<repo>/skills
目标：~/.claude/skills/
已装：36 个技能（或列出指定几个）
跳过：zz-xxx（项目目录里已有一份，保留了你本地版本）
验证：请输入 /zz 试一下
```

## 红线

- 只写技能目标目录，不动 Agent 配置文件里的其他内容
- 覆盖同名技能前必须提醒"会覆盖你本地修改"
- 查重后不允许同名技能同时留在两个会被同时加载的位置
- 安装完成必须给一个可操作的验证步骤，不能只说"装好了"

## 常见坑

- 目录名和 frontmatter 里的 `name` 不一致，导致 Agent 识别不到
- 装到了项目级目录却在别的项目里找不到：先确认用户要全局还是项目级
- 复制时漏掉技能目录里的附属文件（脚本、模板）：始终整个目录复制
