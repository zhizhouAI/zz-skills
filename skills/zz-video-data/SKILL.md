# zz-video-data · 视频数据与文字稿

## 一句话

按链接取视频数据和口播稿，缺凭证就明说。

## 用与不用

适合用的场景：

- 给一条已发布视频整理数据汇报（播放、点赞、评论、互动比）
- 要视频里说的话的文字稿，用来改文章或做二次剪辑
- 定期汇总多条视频数据做周报
- 商单复盘：把投放视频的数据和口播里承诺过的点对起来看

不该用的场景：

- 想抓别人的私密数据（未公开播放量、后台明细）——平台不给就是不给
- 要实时盯数据变化——那是监控系统的活
- 想下载视频文件本身——那是下载工具的活，本技能只管取数和转写
- 直播内容——数据口径和点播完全不同，别混着算

## 开工前要什么

必需信息：

- 视频链接（能打开的完整链接或短链）

可选信息：

- 本地视频文件（有它转写最稳）
- 现成字幕文件（SRT、剪映导出的稿子都行）
- 创作者后台的数据截图或导出表（播放量通常只有创作者自己看得到）
- 竞品对标视频链接（要做对比时一起给）

用户没给时的默认假设：

- 只有链接、没配任何工具：只整理公开可见的数据，缺口列清楚，给配置引导
- 没说要哪些数据：默认给播放、点赞、评论、发布时间四项
- 没说文字稿格式：默认给带时间戳的逐段文本
- 用户只发来一个链接一句话：先回一张「能取什么」清单让他确认，再动手

贯穿示例：新消费品牌「野莓咖啡」的运营小周丢来一条抖音短链，说：「老板只要两样：数字和他说了啥。」又补了句：「别给我整估的数，老板会当真。」视频 3 分 48 秒。播放 12.6 万来自创作者后台截图，点赞 4302、评论 217 从公开页抄到，口播稿用剪映导出的 SRT（96 段）。转发数截图里没有，标「未获取」，让小周去后台补一张。

## 怎么做

1. **拆链接认平台**

   做什么：看域名和短链形态判断平台，提出视频 ID：
   - B站：BV 号可查公开的标题、点赞、评论、发布时间
   - 抖音：短链展开后公开页见点赞评论，播放量在创作者后台
   - 小红书、视频号：多数数据仅创作者可见，先按缺口路线走
   判断标准：说得出平台和 ID。说不出来就先问，不猜。
   中间产物：一行「平台＋ID＋可见数据范围」的记录。示例：抖音，公开页只见点赞评论，播放量在后台。

2. **盘本地能力**

   做什么：查三样，逐项记录：
   - 接口与凭证：有没有平台开放接口、API key 或登录态配置
   - 转写工具：本地 whisper、剪映导出的 SRT、妙记链接
   - 用户手里的材料：后台数据截图、字幕文件、口述数字
   盘完写一句「能用什么、缺什么」。
   判断标准：缺什么写得出来，才往下走。
   中间产物：能力盘点表。示例：有 SRT，无接口凭证，有后台截图。

3. **拉数据，每个数标来源**

   做什么：公开能取的直接取；取不到的列「未获取」，同时告诉用户去创作者后台哪一页抄，或把截图里的数报给录入。整理成数据卡。
   口径写死：播放量和曝光量分开记，绝不混用；抓取时间写进来源字段。
   判断标准：每个数字后面都挂着来源字段；估算值一个都不许有。
   中间产物：数据卡。示例：播放 126,000（来源：后台截图）、点赞 4,302（公开页）、转发「未获取（截图缺此项）」。

4. **取文字稿**

   做什么：有本地文件就转写；有 SRT 就直接清洗；只有链接就说明需要下载视频或请用户贴稿，不凭链接猜内容。
   清洗口径：合并被切断的半句，去掉纯语气词段；能分辨说话人时标注说话人。
   判断标准：稿子分段带时间戳；没有时间戳要标明「无时间戳」。
   中间产物：带时间戳的文字稿。示例：96 段洗成 41 段，开头是「大家好，今天给大家看我们的新品冷萃」。

5. **汇总输出＋缺口清单**

   做什么：数据卡在前，文字稿在后，最后附缺口清单：哪些没拿到、为什么、怎么补（去哪一页抄、装什么工具）。
   顺序固定：这三段谁在前谁在后不换，看的人好找。
   判断标准：看这份输出就知道还缺什么、去哪补，不用再问。
   中间产物：完整交付文档。

6. **没凭证时给配置引导**

   做什么：把补齐路径写具体：转写装哪个工具、凭证去平台哪里申请、配置写到哪个环境变量或文件；同时给一条「手动路线」——用户自己从后台抄数、从剪映导 SRT。引导后等补齐再跑第 3、4 步。
   写法要求：引导用祈使句，装什么、点哪里、贴到哪，一步一行，不写原理。
   判断标准：用户照着清单能自己补齐，不用来回问。
   中间产物：配置引导清单。示例：给小周两条路——配平台开放凭证，或手动贴后台截图。

7. **交前复核对口径**

   做什么：把数据卡里每个数和来源字段再对一遍；文字稿抽 3 段对视频原声；缺口清单里每条都有下一步动作。
   判断标准：找不到一个没有来源的数字，找不到一条没有动作的缺口。
   中间产物：复核记录，一行一条。

## 交付长什么样

```
# 视频数据卡：《新品冷萃首发》（抖音）
链接：v.douyin.com/ixxxxx｜发布：2026-11-12｜时长 3:48

| 指标 | 数值 | 来源 |
|------|------|------|
| 播放 | 126,000 | 创作者后台截图（用户提供） |
| 点赞 | 4,302 | 公开页 2026-11-20 抓取 |
| 评论 | 217 | 公开页 2026-11-20 抓取 |
| 转发 | 未获取 | 后台截图无此项；请补：后台-数据中心-作品数据 |
| 完播率 | 未获取 | 仅后台可见，去「数据中心-作品数据」看 |

互动比：点赞/播放 ≈ 3.4%（口径备注：分母为后台播放量）

# 语音文字稿（节选，完整稿随文件交付）
[00:02] 大家好，今天给大家看我们的新品冷萃……
[00:41] 它用的是埃塞俄比亚的豆子……
[01:20] 有人问苦不苦，其实是果酸带来的回甘……

# 缺口清单
- 转发数：后台截图没有该项，去「数据中心-作品数据」补一张截图即可
- 完播率：同上一页可见，顺路一起抄
- 说话人标注：全片一人讲述，已按单人稿处理

# 附：配置引导（未配置接口凭证时附上）
1. 转写：继续用剪映导出 SRT；或本地装 whisper 后告诉我路径
2. 自动取数：去平台开放平台申请创作者接口，凭证配到环境变量再跑
3. 都不想配：每次把后台截图发我，我手动录入并逐项标来源
```

## 红线

- 没取到的数据一律写「未获取」，禁止填估算值；每个数字都能指出来源
- 输出里区分「公开可见」和「仅创作者可见」，不拿点赞数冒充播放量
- 不绕登录态抓数，同一请求失败 2 次就停下说明，交给用户处理
- 文字稿标时间戳；没有就明确写「无时间戳」，不确定的段落标「待校对」
- 没配凭证时，交付物是引导清单，不是编出来的报告

## 常见坑

- 把第三方页面显示的节选数字当全量数据，跟后台对不上还以为抓错了
- B站分 P 视频只取了 P1，后面几 P 的数据全丢
- 转写稿不洗直接交：半句话、空段、语气词堆一堆，没法用
- 把「播放量」和「曝光量」混着写，汇报口径被追问
