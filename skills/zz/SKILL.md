# zz · 调度台

## 一句话

先弄清你要什么结果，再决定动用哪些技能、按什么顺序推进。

## 用与不用

**用：**
- 一句话说不清要做什么，想让 Agent 先帮你理思路
- 一件事明显要分几步（比如先诊断、再写稿、再查风险）
- 你记得库里有类似的技能，但不确定是哪一个
- 想从上次中断的地方接着做

**不用：**
- 事情很小，一句直接的回答就够了（调度本身也有成本）
- 你已经明确知道要用哪个技能，直接输入它的名字更快

## 开工前要什么

- 必需：用户想达成的最终结果（哪怕很模糊也行）
- 可选：目前手头有什么材料、卡在哪一步、时间要求
- 默认假设：用户什么都没说清时，先问一个问题，不要一次问五个

## 怎么做

1. **问结果**：用一句话向用户确认"你最终想要拿到什么"。用户描述里已经有的就直接用，不重复问。判断标准：能把结果写成一句可验收的话（"一份能发的小红书文案"），就进入下一步
2. **问卡点**：确认用户现在处于哪一步：还没想清楚 / 想清楚了没材料 / 有材料没成品 / 有成品要检查。判断标准：四个阶段必居其一，说不清就默认"还没想清楚"
3. **对照路由表**：按下面两张表选技能。判断标准：能一个技能解决的绝不用两个；必须接力的按"产物传递"排序（上一个技能的交付物直接作为下一个的输入，不让用户复述）
4. **说明安排**：开始动手前，用两三句话告诉用户：我打算先用什么、再用什么、为什么。需要用户定方向的（比如发哪个平台、定什么价位），把选项列出来让用户选，不替用户拍板
5. **推进与收尾**：在同一个对话里逐步推进。每个技能交付后，问一句"接下来：继续下一步 / 调整这一步 / 先到这"。收尾时如果还有没做完的链条，建议用户存档（`zz-save-point`）

### 路由表 · 按结果找技能

| 你要的结果 | 首选技能 |
| --- | --- |
| 想清楚一个问题/概念 | `zz-ask-reset`、`zz-term-map` |
| 诊断生意哪里出了问题 | `zz-biz-check` |
| 决定选题值不值得写 | `zz-topic-score` |
| 拿到一份内容方案 | `zz-topic-plan` |
| 拿到标题/封面/开头 | `zz-hook-three` |
| 稿子改得打动人 | `zz-flat-fix` |
| 稿子去 AI 味 | `zz-ai-trace`（检测）→ `zz-human-tone`（改口语） |
| 发布前查风险 | `zz-risk-line` |
| 排版公众号图文 | `zz-gzh-html` |
| 让自己动起来 | `zz-stuck-break` |
| 记录并复盘决定 | `zz-choice-log` |

### 路由表 · 常见接力链

| 场景 | 顺序 |
| --- | --- |
| 从选题到发布 | `zz-topic-score` → `zz-topic-plan` → 用户写稿 → `zz-risk-line` → `zz-gzh-html`（如发公众号） |
| 稿子流量差 | `zz-flat-fix` 与 `zz-hit-autopsy` 各出一份分析 → 汇总对比 → 定改法 |
| 学个新东西 | `zz-term-map` → `zz-course-loop` → 每篇完稿走 `zz-flat-fix` |
| 大决定不拍脑袋 | `zz-best-answer` → `zz-round-table` → `zz-choice-log` |

## 交付长什么样

```text
【安排】
你要的结果：____
当前阶段：还没想清楚 / 没材料 / 没成品 / 要检查
我的安排：先用 zz-xxx 做____，产出____；再用 zz-yyy 做____
需要你定的事：A 或 B（选一个，或者告诉我你的想法）

【推进中】
（每个技能的交付内容 + 下一步选项）
```

## 红线

- 每次开始前必须向用户复述"你要的结果"，且用户没确认方向前不产出正式交付物
- 需要用户拍板的地方只列选项和各自代价，不替用户选
- 简单问题直接回答；调用两个以上技能时必须先说明整体安排
- 技能之间传递产物，不要求用户把同样的话说两遍
- 对话结束时若链条未完成，必须提示可存档，并说明存档会记下什么

## 常见坑

- 一次性问用户五个问题：先问最关键的一个，边推进边补
- 把简单问题套上重型流程：判断"一句直接回答"够不够，够就不调度
- 接力链里每个技能各问各的：上一个技能的交付物就是下一个的输入，别让用户复述
