# zz-skills 技能写作规范

新建或修改技能必须遵守本规范。`zz-skill-forge` 引用本文件；CI 按本规范做门禁。

## 语言

- 简体中文，口语化短句
- 禁用空话：赋能、抓手、闭环、底层逻辑、顶层设计、心智、颗粒度
- 不堆排比，不写「让我们」
- 共享词表见 `shared/wordlists/`，AI 腔黑名单对技能文本本身同样适用

## 结构（九段，顺序不可变）

1. YAML frontmatter：`name`（与目录名一致）、`description`（何时用+干什么+触发词，80~150 字）、`status`（stable / beta / experimental）
2. `# 名字 · 中文标题`
3. `## 一句话`：30 字内
4. `## 用与不用`：适合 3~5 条；不该 2~4 条，每条说明为什么
5. `## 开工前要什么`：必需 / 可选 / 默认假设；内容类技能加 `profile/` 档案引用条
6. `## 怎么做`：4~8 步；每步 = 做什么 + 判断标准 + 中间产物
7. `## 交付长什么样`：输出模板放代码块
8. `## 红线`：3~5 条，每条可检查（写明怎么验），不写「保证质量」这类空话
9. `## 常见坑`：2~4 条，现象 + 规避方法

## 内容要求

- 每个技能至少 1 个贯穿全文的具体示例：有行业、有数字、有对话感
- 方法论可引用公开通用框架（JTBD、5-Why、MECE 等），但操作化表述必须自创
- 涉及合规的技能（zz-risk-line 等）末尾加「免责与词表说明」小节，引用 `shared/wordlists/` 并标注更新日期
- 技能之间通过产物衔接：交付物必须能让下一个技能直接使用，不要求用户复述

## 工程要求

- 行数 150~260（入口/基建类技能 ≥60 即可）
- 每个技能在 `evaluation/` 下有对应 `<name>.exam.md` 考题（≥3 道）
- 修改技能后运行 `./scripts/lint_skills.py` 和 `./scripts/evaluate.sh`，全绿才能提交
- 版本号变更写进 `CHANGELOG.md`
