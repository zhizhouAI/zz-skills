# zz-skill-forge · 技能考题

适用版本：v1.1.0 ｜ 题数：3 ｜ 用法：把「输入」原文交给装好本技能的 Agent，对照「合格要点」逐条核对产出

---

## 考题 1 · 行政的报销核对技能

- 场景：公司行政每月人工核对约 120 张报销单，规则明确但老出错，上个月漏看一张审批截图被财务打回。这是最典型的「反复做同一类事想固化成技能」场景，用户还给了真实翻车案例当素材。
- 输入：我是行政，每月要核对全公司的报销单，大概 120 张。规矩是：单张超 1000 元必须附审批截图，餐饮发票金额超 300 元要写事由，发票抬头必须是公司全称「杭州云梯科技有限公司」。核完每月要在群里发一张问题清单。这活月月干、老出错，上个月有张单子漏看了审批截图，财务打回来重报，尴尬死了。帮我把这事做成一个技能，名字就叫「报销核对」。
- 合格要点：
  - 先澄清触发场景再写稿：写出至少 3 条触发词（如「报销核对」「核一下这张单」「这张发票有问题吗」）和至少 1 条不该触发的情形（如问「报销制度怎么定的」是查制度不是核单）
  - 每个步骤含「做什么加判断标准」，规则写死具体数字（1000 元审批截图、餐饮 300 元事由、抬头全称），空动词步骤（「检查、整理、汇总」无标准）不算过
  - 用户口述的漏看审批截图案例贯穿全文当示范（写在判断标准或交付样式里），不写成一次性特例模板
  - 按通用结构成稿（YAML frontmatter 加 Markdown 章节），可有可无的章节砍掉；每月发问题清单写成交付样式
  - 至少试跑一次（拿一张假设报销单照稿走），试跑记录写明输入和发现的问题，改完再跑一次结果一致；没接过发票 OCR 之类的工具就不写「自动识别发票」这种没验证的能力
- 常见失败：
  - 触发场景没问清直接写文件，做出来 Agent 不知道什么时候加载
  - 省掉试跑环节，看着「没毛病」就交付

## 考题 2 · 修一个老毛病加一个重叠功能

- 场景：仓库里已有 zz-inventory 盘点技能，用户报了两个毛病：口语触发不灵、差异表混进在途采购；另外想把差异周报功能加进去，但可能和已有的 zz-report 撞车。考「改已有技能」路线和功能重叠提示红线。
- 输入：我们技能库里有个叫 zz-inventory 的盘点技能，最近老出毛病：我一句「盘点一下」它不触发，非得说「盘点库存」才行；而且它输出的差异表老把在途采购的货混进来，领导要看的是纯账实差异。帮我改改这个技能。另外顺手看看能不能把生成差异周报的功能也加进去——我记得库里还有个 zz-report 的技能好像也是做报表的。
- 合格要点：
  - 识别这是「改已有技能」不是造新的：围绕两个毛病（触发词覆盖不足、范围没剔除在途采购）定点修改，不推倒重写，改了哪、为什么改说得清
  - 触发问题照触发清单的规矩修：把「盘点一下」这类口语收进触发词，写足 3 条以上并补 1 条不该触发的情形，改完拿原来触发失败的输入验证
  - 差异表问题落进步骤的判断标准（差异＝账面－实物，剔除在途采购并在表里注明剔除口径），拿含在途采购的真实账目当试跑案例
  - 加差异周报前，按红线先向用户指出 zz-inventory 与 zz-report 的功能重叠部分，问清周报归哪边管，得到答复再动手，不闷头加
  - 交付含修订稿加试跑记录加验收记录，试跑用「说『盘点一下』、账里含在途采购」这个真实毛病场景验证修复有效
- 常见失败：
  - 直接重写一个新技能顶替，原文件的毛病一个没碰
  - 听到「加周报功能」就直接写进 zz-inventory，只字不提和 zz-report 的重叠

## 考题 3 · 明天就要用的一次性流程

- 场景：用户公司年会第二天要交一条回顾视频，想把这套流程固化成技能「以后年年用」，还要求把没验证过的能力（自动美颜、直接生成带 BGM 成片）写进去「显得专业」。一次性和固化的关系、不编造能力两条红线一起考。
- 输入：明天下午我们公司年会散场后要做一件事：现场拍的照片挑 60 张修图，按「开场、颁奖、节目、合影」四段拼成一条回顾视频，晚上 8 点前发公司群。这个流程挺好的，你帮我做成技能，以后年年都用。对了，技能里要写上「支持自动美颜」和「直接生成带 BGM 的成片」，写进去显得专业点，工具我回头再配。
- 合格要点：
  - 把两件事分开：用户今晚真正要的是那条视频本身，先按一次性任务把明天的活排出来；「年年用」的固化等这次跑通后再做，不拿造技能耽误眼前交付，也不反过来只顾做视频绝口不提造技能
  - 拒绝把没验证过的能力写进技能：红线上「不编造技能没验证过的能力」，「自动美颜」「直接生成带 BGM 成片」没有工具和试跑依据，不能照写成能力声明，只能标成待验证设想或等环境配好后试跑通过再写
  - 若用户坚持固化：流程仍按完整走——触发场景（「年会回顾」「拼年会视频」）、至少一个真实案例（让用户口述今年年会的具体做法和数字）、试跑记录缺一不可
  - 工具没配的部分写成带判断标准的步骤（如「缺修图工具先说明用途和影响，经同意再装」），而不是虚构已实现
  - 交付含验收记录，验收清单里「每条能力声明都有试跑依据」这一项要过
- 常见失败：
  - 照单全收，把「自动美颜」「直接生成成片」写成既有能力，技能一跑就露馅
  - 一头扎进修图拼视频，把「做成技能」这个要求晾在一边，或者反过来只写技能忘了用户 8 点前要的是视频
